# Claude Code Best Practice — 83 совета для профессиональной работы

> Систематизированный справочник best practices для Claude Code. "От vibe coding к agentic engineering — практика делает совершенство." 10+ готовых workflow'ов от сообщества и создателей Claude Code.

---

## Введение

Репозиторий собирает 83 практических совета для работы с Claude Code. Это не теория — это опыт профессионалов, которые используют Claude Code для сложных проектов.

**Основной девиз:** Challenge Claude — don't babysit. Просто скажи "fix" для багов, не объясняя как.

## 7 основных тем

### 1️⃣ Subagents (подагенты)

**Идея:** Вместо одного большого агента — несколько специализированных, которые общаются между собой.

**Best practices:**
- Один агент = одна роль (исследователь, разработчик, тестировщик)
- Агенты передают результаты через четко определенный интерфейс
- Используйте `agent.run()` для запуска другого агента из текущего
- Не дублируйте логику между агентами

**Когда использовать:** Сложные проекты (3+ участников), где каждый работает на своём участке.

---

### 2️⃣ Commands (слеш-команды)

**Идея:** Быстрые команды вместо долгих диалогов.

**Best practices:**
- `/plan` — перед сложными задачами
- `/review` — проверка кода перед интеграцией
- `/test` — запуск тестов
- Создавайте свои команды для повторяющихся задач

**Как создать:** `.claude/commands/my-command.md` с описанием и промптом.

**Когда использовать:** Когда задача повторяется 3+ раза — сделайте команду.

---

### 3️⃣ Skills (навыки)

**Идея:** Готовые расширения функциональности — видео, анализ, интеграции.

**Best practices:**
- Используйте awesome-claude-skills как источник готовых решений
- Одна задача = один скилл
- Скилл должен быть переиспользуемым (не под конкретный проект)
- Документируйте скилл: что делает, примеры использования

**Когда создавать свой:** Когда готовых нет или нужна кастомизация под вашу задачу.

---

### 4️⃣ Workflows (рабочие процессы)

**Идея:** Готовые цепочки действий для типичных задач.

**10+ готовых workflow'ов в репозитории:**
- Code Review Workflow
- Video Processing Workflow
- Content Generation Workflow
- Data Analysis Workflow
- Project Setup Workflow
- Testing Workflow
- Deployment Workflow
- (и ещё 3+)

**Best practices:**
- Workflow = цепочка команд + скиллов
- Документируйте: входные данные, шаги, результаты
- Делайте workflow'ы переиспользуемыми

**Как использовать:** Скопируйте готовый workflow из репозитория, адаптируйте под свой проект.

---

### 5️⃣ MCP Servers и Hooks

**MCP (Model Context Protocol):**
- Подключите внешние источники (GitHub, Slack, Figma)
- Дайте Claude доступ к данным без запросов

**Best practices:**
- Используйте MCP для интеграции с системами
- Не загружайте большие данные вручную — подключите через MCP
- Проверьте, есть ли готовый MCP сервер (есть 90k+ в каталоге)

**Hooks (автоматизация):**
- SessionStart, PostToolUse, PreCompact
- Используйте для классификации, валидации, логирования

---

### 6️⃣ Memory и Settings

**Memory (память):**
- SOUL.md, MEMORY.md, GOALS.md
- Projects для постоянного контекста

**Best practices:**
- Используйте Projects вместо повторного загрузки файлов
- Память должна быть структурирована (YAML, markdown)
- Индексируйте память для быстрого поиска

**Settings (.claude/settings.json):**
- Разрешения (permissions)
- Переменные окружения
- Включённые плагины

### 7️⃣ Горячие темы

#### Ultrareview
**Что:** Мультиагентный code review через облако.
**Использование:** `/code-review ultra` (платно, но стоит)
**Когда:** Перед деплоем в production.

#### Auto Mode
**Что:** Claude работает самостоятельно без ваших интервенций.
**Best practices:**
- Дайте чёткое задание
- Установите таймаут
- Проверьте результат перед использованием

#### Fast Mode
**Что:** Ускоренный режим (Opus с оптимизациями).
**Когда:** Нужны быстрые ответы, качество менее критично.

#### Agent Teams
**Что:** Несколько агентов работают на одной задаче.
**Best practices:**
- Один лидер, остальные исполнители
- Четкое разделение ответственности
- Регулярные синхронизации

#### Computer Use
**Что:** Claude может кликать в браузер, заполнять формы.
**Когда:** Автоматизация UI-тестов, скрейпинг с интерактивными сайтами.

#### Code Review
**Best practices:**
- Используйте `/review` перед каждым merge
- Ищите не ошибки, а паттерны
- Попросите Claude разнести собственный код (режим критика)

#### Scheduled Tasks
**Что:** Агент работает по расписанию.
**Примеры:** Ежедневный диджест, еженедельный отчет, мониторинг.

#### Voice Dictation
**Что:** Диктовать промпты голосом.
**Когда:** Быстрые команды, мозговой штурм.

## 83 Совета по категориям

### Промптинг (10 советов)

1. Challenge Claude — скажи "fix it" вместо подробного объяснения
2. Дай примеры правильного ответа
3. Если нужна точность — запрети галлюцинации ("если нет данных — скажи об этом")
4. Используй температуру (effort level) для контроля качества
5. Одно уточнение лучше трёх предположений
6. Давайте контекст целиком, не по кусочкам
7. Используйте Projects вместо повторной загрузки
8. Попросите Claude разнести собственный ответ критикой
9. Задавайте конкретные критерии успеха
10. Используйте режим критика перед финальным ответом

### Планирование (8 советов)

1. Всегда начинайте со `/plan`
2. Разбивайте задачи на шаги (3+ шагов)
3. Добавьте критерии успеха в план
4. Используйте модель от простого к сложному
5. Если план > 20 шагов — разделите на подзадачи
6. Проверьте зависимости между шагами
7. Дайте приблизительные сроки для каждого шага
8. Пересмотрите план если задача изменилась

### Управление контекстом (12 советов)

1. Projects для постоянного контекста
2. Индексируйте память (YAML, структурированный формат)
3. Не загружайте одно и то же дважды
4. Используйте `/clear` перед новой задачей
5. Держите контекст < 100k токенов (перейти на Opus если больше)
6. Архивируйте старые беседы (не пишите всё в одном чате)
7. Используйте MCP для интеграций вместо загрузки данных
8. Сжимайте контекст (убирайте лишнее)
9. Используйте effort для контроля size контекста
10. Храните в Projects, а не в памяти чата
11. Обновляйте памяти после каждой крупной сессии
12. Не смешивайте разные проекты в одном чате

### Работа с сессиями (7 советов)

1. Одна сессия = одна задача (не смешивайте)
2. Сохраняйте сессии в Projects
3. Используйте `/cost` перед завершением (сколько потратили)
4. Завершайте сессию после 50+ сообщений (контекст разрастается)
5. Проверьте `/status` на предмет лимитов
6. Используйте Fast Mode для прототипов
7. Используйте Opus для критических задач

### Работа с агентами (15 советов)

1. Один агент = одна роль
2. Agenty-to-agent коммуникация через интерфейсы
3. Используйте `agent.run()` для вызова другого агента
4. Документируйте ожидаемые входы/выходы
5. Не дублируйте логику
6. Каждый агент должен быть независимым
7. Тестируйте агента отдельно перед интеграцией
8. Используйте версионирование для агентов
9. Добавьте fallback если агент упадёт
10. Логируйте выход каждого агента
11. Не делайте агента "всезнающим"
12. Используйте Teams для параллельной работы
13. Синхронизируйте агентов через очередь сообщений
14. Мониторьте производительность каждого агента
15. Обновляйте агентов независимо

### Команды и Skills (18 советов)

1. Одна команда = одна задача
2. Переиспользуемые команды (не под конкретный проект)
3. Документируйте команду: что, как, примеры
4. Skills из awesome-claude-skills перед написанием своего
5. Скилл должен решать универсальную задачу
6. Версионируйте скиллы
7. Тестируйте скилл на разных данных
8. Не делайте скилл слишком сложным
9. Если скилл > 200 строк — разделите
10. Добавьте примеры использования
11. Используйте skill-creator для создания
12. Скилл должен быть fault-tolerant
13. Логируйте ошибки внутри скилла
14. Не скрывайте ошибки — дайте контекст
15. Обновляйте скилл если поменялись требования
16. Не создавайте скилл если это один раз
17. Делайте скилл настраиваемым (параметры)
18. Документируйте зависимости скилла

### Отладка (13 советов)

1. Используйте `/investigate` для систематической отладки
2. Воспроизведите ошибку в минимальном примере
3. Покажите Claude выход с ошибкой + контекст
4. Не гадайте — проверьте логи
5. Изолируйте переменную (меняйте по одной)
6. Используйте разбор багов (Challenge Claude)
7. Если бага нет в изоляции — проблема в интеграции
8. Добавьте логирование на каждом шаге
9. Используйте assert для проверок
10. Сделайте ошибку воспроизводимой
11. Тестируйте на разных входах
12. Используйте breakpoint если можете
13. Документируйте ошибку и решение

### Прочее (10 советов)

1. Используйте Auto Mode но проверяйте результат
2. Не полагайтесь на память чата — используйте Projects
3. Регулярно обновляйте свои скиллы
4. Участвуйте в сообществе Claude Code
5. Следите за обновлениями (новые features)
6. Используйте Computer Use для UI-автоматизации
7. Интегрируйте через MCP вместо ручной загрузки
8. Версионируйте всё (агенты, скиллы, workflow'ы)
9. Документируйте — даже если кажется очевидно
10. Делитесь своими workflow'ами с сообществом

## Практический пример: от vibe coding к agentic engineering

**Вибо-кодинг (антипаттерн):**
```
Я: "Напиши функцию X"
Claude: [пишет]
Я: "Нужно ещё Y"
Claude: [переписывает]
...
Результат: хаотичный, непредсказуемый
```

**Agentic Engineering (best practice):**
```
1. `/plan` — разбиваю на шаги
2. `/create-agent researcher` — исследует требования
3. `/create-agent developer` — пишет код
4. `/create-agent reviewer` — проверяет
5. Агенты общаются и согласовывают
Результат: структурированный, надежный
```
