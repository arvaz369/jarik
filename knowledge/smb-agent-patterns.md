# SMB Agent Architecture Patterns — Мультиагентные системы для малого бизнеса

> Архитектурные паттерны для построения мультиагентных систем, специализированных на автоматизации SMB операций. Основано на анализе Anthropic Claude for Small Business и 15+ готовых workflows.

---

## Введение

Малый бизнес состоит из 5-7 критических процессов:
- Финансы (зарплата, reconciliation, маржинальность)
- Операции (счета, платежи, отслеживание)
- Продажи (pipeline, лиды, кампании)
- HR (контракты, recruitment)
- Маркетинг (контент, кампании)

Каждый процесс требует своего "эксперта", но они работают как одна система.

**Решение:** Мультиагентная архитектура с центральным Claude как оркестратором.

---

## 5 Ключевых Архитектурных Паттернов

### 1️⃣ Decomposition (Разложение)

**Задача:** Большая бизнес-задача → специализированные подзадачи

**Как это работает:**

```
Пользователь: "Закрой месячный период"
        ↓
Claude (оркестратор) анализирует контекст:
  1. Финансовый агент → reconciliation в QuickBooks
  2. Sales агент → закрытие месячного pipeline
  3. HR агент → начисление бонусов
  4. Report агент → сборка итогового отчета
        ↓
Результат: Месяц закрыт, все агенты отработали
```

**Ключевой момент:** Каждый агент знает одну область, но оркестратор знает как их координировать.

**Для Jarik:** Когда первый SMB клиент, разбиваешь его операции на 5-7 специализированных агентов, не делаешь один "супер-агент".

---

### 2️⃣ State Management (Сохранение контекста)

**Проблема:** Если каждый агент запускается отдельно → теряется контекст.

**Решение:** Projects в Claude Code как persistent memory для каждого workflow'a

**Архитектура:**

```
Project: "Client-SMB-May-2026"
├── context/
│   ├── financial-snapshot.md (текущие финансы, счета)
│   ├── sales-pipeline.csv (сделки, стадии, история)
│   ├── team-structure.md (кто кого ведет, иерархия)
│   └── business-rules.md (лимиты, правила, исключения)
├── agents/
│   ├── finance-agent.md (промпт + история решений)
│   ├── sales-agent.md
│   └── operations-agent.md
└── workflows/
    ├── month-close.md
    ├── payroll.md
    └── campaign-launch.md
```

**Как использовать:**
- Каждый агент прочитывает Project один раз → знает весь контекст
- Кэш сохраняет, нет повторной загрузки
- История решений в папке → агент учится на своих ошибках

**Для Jarik:** Projects → идеальное место для хранения всей информации о SMB клиенте.

---

### 3️⃣ Trust & Verification (Проверка и Одобрение)

**Правило:** Любое действие во внешних системах → plan → approval → execute

**Диаграмма:**

```
Агент генерирует план:
"Я хочу:
  1. Отправить 15 счетов просроченным клиентам
  2. Начислить штрафы
  3. Отправить уведомление в Slack"
        ↓
Пользователь (или второй агент-валидатор) одобряет
        ↓
План исполняется → действия применяются
```

**Почему это важно:**
- Защита от hallucinations (агент генерирует неправильный план → перехватываем)
- Audit trail (кто одобрил, когда, почему)
- Контроль (пользователь остается в курсе)

**Уровни автономности:**

| Уровень | Кто решает | Когда использовать |
|---------|-----------|-------------------|
| Manual | Только пользователь | Первая неделя, критичные операции |
| Assisted | Claude предлагает, пользователь выбирает | Операционные задачи |
| Autonomous | Claude решает, логирует, пользователь смотрит отчет | Рутина (зарплата, reconciliation) |

**Для Jarik:** Начинаешь с Manual/Assisted, потом когда система "выучится" → Autonomous.

---

### 4️⃣ Multi-Tool Orchestration (Выбор правильного инструмента)

**Задача:** Агент должен знать, какой инструмент использовать для какой задачи.

**Примеры решения:**

```
Задача: "Где-то бага с платежом клиента Acme"
  → Проверить QuickBooks (финансовые записи)?
  → Проверить PayPal (платежные шлюзы)?
  → Проверить Stripe (если есть)?
  → Проверить CRM (контакты)?

Агент должен:
1. Понять категорию проблемы
2. Выбрать правильный источник (один первым!)
3. Если там не найти → переходить к следующему
```

**Реализация в Claude:**

```
Промпт для агента:

У тебя есть доступ к:
- QuickBooks MCP: платежи, счета, reconciliation
- HubSpot MCP: контакты, деалы, письма
- PayPal MCP: платежи и переводы
- Slack MCP: логи, уведомления

Алгоритм выбора:
1. Финансовая проблема → QuickBooks
2. Контакт / деал / история → HubSpot
3. Платеж / пополнение → PayPal
4. Если не уверен → спроси пользователя

Не пытайся проверить все сразу!
```

**Для Jarik:** При настройке агента для клиента → картировать его инструменты и дать четкие правила роутинга.

---

### 5️⃣ Data Privacy (Соблюдение прав доступа)

**Правило:** Если сотрудник не видит данные в исходной системе → не видит через Claude.

**Пример:**

```
Иван (менеджер по продажам) может видеть:
  ✅ Свои сделки
  ✅ Прогноз по своему отделу
  ❌ Зарплату других сотрудников
  ❌ Прибыль компании

Claude для Ивана НЕ должен видеть:
  ❌ Зарплаты других
  ❌ Финансовые отчеты
  ❌ Стратегические решения

Архитектура:
- Каждому агенту свой API ключ с соответствующими правами
- Project раскладывается по папкам с access rules
- Если Иван запросит данные которые не может видеть → отказ
```

**Для Jarik:** При настройке клиента → отдельный Project для каждой роли (CEO, CFO, Manager, Team Member) с соответствующими доступами.

## Примеры из реальной жизни

### Purity Coffee (COO)

> "показало мне проблемы, которые я не знал о себе"

**Что случилось:**
- Finance Agent → анализ маржинальности выявил убыточную товарную категорию
- Sales Agent → выявил клиентов с просроченными платежами
- Результат: COO переструктурировал ассортимент, закрыл убытки

**Паттерн:** Агент как аналитик, который видит то, что люди пропускают.

### Simple Modern (CEO)

> "часы глупого анализа исчезли, хочу всю организацию"

**Что случилось:**
- Workflow: "Месячный отчет" раньше = 15 часов ручной работы (Excel, посчитать, собрать)
- Теперь = Finance Agent запускается, 10 минут → отчет готов
- Результат: CEO хочет масштабировать на всю организацию

**Паттерн:** Агент как экономия времени, которая может быть переинвестирована в стратегию.

### MidCentral Energy

**Что случилось:**
- Operations Agent → освобождает команду от клерикальной работы
- Команда теперь работает над стратегическими инициативами
- Результат: производительность + смысл в работе

**Паттерн:** Агент как освобождение команды для более ценной работы.

## Как применять к Jarik

### Фаза 1: Прототип (сейчас)

**Выбрать один SMB клиент** (реальный или гипотетический):
- Тип: 10-50 человек, 1-3 млн выручки
- Процессы: Финансы + Sales (основные боли)

**Построить 2 агента:**
1. Finance Agent (зарплата + reconciliation)
2. Sales Agent (pipeline + лиды)

**Убедиться что работают все 5 паттернов:**
- ✅ Decomposition: два отдельных агента
- ✅ State Management: Project с общим контекстом
- ✅ Trust & Verification: план → одобрение → исполнение
- ✅ Multi-tool Orchestration: QuickBooks vs. HubSpot
- ✅ Data Privacy: разные API ключи

### Фаза 2: Расширение

**Добавить 3-5 агентов:**
- Operations (счета, платежи)
- HR (контракты, зарплата)
- Marketing (контент, кампании)

**Результат:** Полноценная SMB система из 5-7 агентов.

### Фаза 3: Демонстрация клиентам

**Использовать паттерны как selling point:**
- "Мы специализируемся на мультиагентных SMB системах"
- "Каждый процесс → отдельный агент, но они работают как одна система"
- "Начинаем с Manual (вы контролируете), потом переходим на Autonomous (экономия времени)"
