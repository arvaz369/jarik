# Облако vs Obsidian — выбор архитектуры памяти для агента

> Справка для внедрения нейросотрудников. Когда использовать каждый подход, их плюсы и минусы.

---

## Краткое сравнение

| Характеристика | Облако (текущее Jarik) | Obsidian Mind |
|---|---|---|
| **Хранение** | GitHub (markdown) + контекст сессии | Локальное (Obsidian vault) + Git |
| **Инструмент** | VS Code, Claude Code | Obsidian + Claude Code/Codex/Gemini |
| **Доступ** | Из любого места (облако) | Локальный + синхронизация через Git |
| **Поиск** | Grep, глобальный поиск | Встроенный поиск Obsidian + QMD (семантический) |
| **Память загрузка** | SessionStart читает файлы из MEMORY.md + memory/ | SessionStart инъектирует контекст (~2-3K токенов) |
| **Автоматизация** | Ручная (добавишь в MEMORY.md сам) | Полуавтоматическая (хуки классифицируют) |
| **Команды** | Нет встроенных команд | 18 встроенных команд (/om-*) |
| **Субагенты** | Описаны, не интегрированы | 9 специализированных субагентов |
| **Кривая обучения** | Низкая (просто редактируй md-файлы) | Средняя (нужно привыкнуть к Obsidian) |
| **Требуемое ПО** | VS Code, Git | Obsidian + Claude Code/Codex + Node.js |
| **Стоимость** | Бесплатно | Бесплатно (Obsidian ~$100 лицензия опционально) |
| **Контроль данных** | На GitHub (потребуется приватный репо) | На машине + GitHub (полный контроль) |

## Облако (текущее решение Jarik)

### Как работает

Архитектура на основе markdown-файлов + контекст, загруженный в SessionStart:

```
├─ SOUL.md         (личность агента)
├─ MEMORY.md       (долгосрочная память, ≤ 200 строк)
├─ GOALS.md        (цели)
├─ memory/         (дневники по дням)
└─ knowledge/      (справочники и инструкции)
```

Когда клиент начинает сеанс:
1. Claude Code загружает файлы SOUL.md, MEMORY.md, GOALS.md в контекст
2. Читает сегодняшний файл из memory/YYYY-MM-DD.md
3. Агент видит полный контекст (~5-10K токенов)
4. Клиент общается естественно, агент работает

### Преимущества

✅ **Простота** — просто редактируешь markdown-файлы  
✅ **Нет зависимостей** — только VS Code и Git  
✅ **Быстрая настройка** — 15 минут вместо часа  
✅ **Стандартный стек** — GitHub + VS Code (уже везде)  
✅ **Облачное хранение** — доступ с любой машины  
✅ **Прозрачность** — видно все файлы в папке  
✅ **Версионирование** — Git сохраняет историю  

### Недостатки

❌ **Ручная память** — сам добавляешь в MEMORY.md  
❌ **Нет команд** — всё через обычный диалог  
❌ **Локальный поиск** — только grep по тексту  
❌ **Загрузка контекста** — иногда нужно перечитать MEMORY.md  
❌ **Масштабирование** — при 500+ заметок трудно ориентироваться  

### Оптимально для

- Стартапы и индивидуальные предприниматели
- Проекты < 100 заметок
- Люди, которые не хотят ещё один инструмент
- Быстрая прототипизация агента

### Примеры использования

- Jarik — личный ассистент Паши
- Малые компании (< 20 человек)
- Локальные ассистенты (один человек + агент)

## Obsidian Mind (локальное)

### Как работает

Полнофункциональное хранилище Obsidian + интеграция с агентом через хуки:

```
Home.md                    Входная точка
CLAUDE.md                  Инструкции для агента
brain/
  ├─ North Star.md         Цели (переиндексируется каждый сеанс)
  ├─ Memories.md
  ├─ Key Decisions.md
  └─ Skills.md
work/
  ├─ active/               Текущие проекты
  ├─ archive/YYYY/         Завершённые
  └─ incidents/
org/people/                По одной заметке на человека
perf/Brag Doc.md          Логирование побед
.claude/commands/          18 встроенных команд
```

Когда клиент начинает сеанс:
1. Хук SessionStart переиндексирует North Star.md
2. Инъектирует контекст (~2-3K токенов)
3. Клиент может вызывать команды (`/om-standup`, `/om-wrap-up`)
4. Хук UserPromptSubmit классифицирует содержимое автоматически
5. Хук PostToolUse валидирует новые заметки

### Преимущества

✅ **Полуавтоматическая память** — хуки классифицируют контент  
✅ **Встроенные команды** — `/om-standup`, `/om-wrap-up` и 16 других  
✅ **Семантический поиск** — через QMD (поиск по смыслу)  
✅ **Граф знаний** — вики-ссылки создаются автоматически  
✅ **Специализированные субагенты** — brag-spotter, context-loader и 7 других  
✅ **Масштабирование** — хорошо работает с 1000+ заметок  
✅ **Obsidian UI** — мощный интерфейс для исследования памяти  
✅ **Производительность** — встроенный Brag Doc, tracking  

### Недостатки

❌ **Требует Obsidian** — ещё один инструмент для клиента  
❌ **Кривая обучения** — нужно привыкнуть к Obsidian  
❌ **Node.js зависимость** — требует Node 22+ для хуков  
❌ **Сложнее настройка** — 1-2 часа вместо 15 минут  
❌ **Локальное хранение** — нужна синхронизация через Git  
❌ **QMD опционален** — без него теряется семантический поиск  

### Оптимально для

- Средние и крупные организации
- Проекты 100+ заметок
- Люди, которые хотят мощный поиск и автоматизацию
- Команды, где нужна интеграция с Slack
- Долгосрочное отслеживание производительности

### Примеры использования

- Крупные компании (> 50 человек)
- Техлиды, которые ведут многие проекты одновременно
- Организации, которые хотят интегрировать Slack, встречи, ревью
- Системы управления знаниями (Knowledge Vault)

## Гибридный подход

Можно комбинировать оба:

1. **Основа** — облачное решение (GitHub + MEMORY.md)
2. **Для расширений** — Obsidian Mind локально у клиента
3. **Синхронизация** — клиент может синхронизировать свой vault с облаком

Пример для среднего клиента:
- Агент работает в облаке (GitHub + VS Code)
- Клиент параллельно ведёт Obsidian для своего поиска и аналитики
- Еженедельно синхронизируют через `/om-vault-upgrade`

## Выбор для нового клиента

### Используй облако, если:

```
✓ Клиент < 10 человек
✓ Проект быстрый (< 3 месяцев)
✓ Клиент не пользуется Obsidian
✓ Нужна быстрая настройка (< 1 часа)
✓ Клиент просто хочет "работающего агента", не infrastructure
```

**Пример**: Стартап нанял тебя сделать агента для маркетинга. Быстро — облако.

---

### Предложи Obsidian Mind, если:

```
✓ Клиент > 20 человек
✓ Проект долгосрочный (> 6 месяцев)
✓ Клиент уже использует Obsidian (или готов)
✓ Клиент хочет семантический поиск по своей памяти
✓ Нужна интеграция со Slack, встречами, ревью
✓ Клиент готов потратить 2-3 часа на настройку
```

**Пример**: Крупная компания нанимает тебя для построения корпоративного AI. Obsidian Mind подойдёт.

---

### Предложи гибрид, если:

```
✓ Клиент растёт (сейчас 10, через полгода 50+)
✓ Нужна и скорость, и функциональность
✓ Есть бюджет на две системы
✓ Клиент готов интегрировать со временем
```

**Пример**: Компания из 15 человек, но планирует 50. Начни с облака, потом мигрируй на Obsidian Mind.

## Миграция облако → Obsidian

Если клиент начал с облака и хочет перейти на Obsidian:

1. Экспортировать MEMORY.md → brain/North Star.md
2. Экспортировать memory/ → соответствующие папки (work/, org/, perf/)
3. Экспортировать knowledge/ → reference/
4. Запустить `/om-vault-upgrade` для переклассификации
5. Запустить `/om-vault-audit` для проверки

Время: 1-2 часа + валидация.
